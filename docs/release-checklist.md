# Релизный чеклист LeavePilot Community

Чеклист релиза **3.0.0**. Проходится сверху вниз, без пропусков; факт полного
прохода фиксируется в GitHub Release notes (раздел 7) — «пройден целиком»
доказывается только так.

Разметка пунктов:

- **[авто: <джоба>]** — пункт проверяет CI: джоба зелёная на merge-коммите
  master, на который ставится тег. Core CI и Core integration прогоняют push
  в master целиком — этот прогон и есть «релизный SHA». Смотреть: вкладка
  Actions, прогон на этом коммите.
- **[руки]** — пункт делает владелец; автоматика его проверить не может.

Версия на весь чеклист одна: **3.0.0** (package.json). Все переменные
окружения — канонические `LEAVEPILOT_*` (устаревшие имена в чеклисте не
упоминаются и использоваться не должны).

- [руки] Все изменения влиты в master через PR. Рабочий каталог чистый:
  `git status --short` пустой. В коммитах нет секретов, ключей подписи,
  лицензий клиентов и дампов баз.

## 6. Тег и публикация

- [руки] Поставить тег v3.0.0 на merge-коммит master и запушить его.
  Дальше publish-workflow делает всё сам:
- [авто: prepare] тег сверен с package.json (3.0.0), релизный SHA зафиксирован;
- [авто: build] образы amd64 и arm64 собраны и запушены по digest,
  community-граница проверена смоук-скриптом, SPDX SBOM сгенерирован
  и приложен к каждому digest, подписи cosign проставлены;

  манифеста зелёный.

  `cosign verify-attestation` по командам из docs/container-images.md
  (раздел про проверку подписи и SBOM). Пакет в GHCR публичный.

## 9. Откат

- [руки] Откат = вернуть `LEAVEPILOT_IMAGE` на предыдущий тег образа
  (полную версию, не latest) и перезапустить compose. Откат миграций — только
  из бэкапа базы, снятого до обновления; ручные деструктивные правки БД — не
  первый путь. До релиза убедиться, что предыдущий тег образа существует
  (теги в GHCR не удаляются) и бэкап снят.
