### Regeneration commands

The exact commands that produced the numbers in this document. Run them from
the repository root; both are read-only with respect to the lockfile.

```sh
# Production dependency graph (what the shipped artifacts carry):
npm sbom --sbom-format spdx --omit=dev > /tmp/sbom-prod.spdx.json

# Full graph including devDependencies (for reference; not shipped):
npm sbom --sbom-format spdx > /tmp/sbom-all.spdx.json

# License summary over the SPDX packages array:
jq -r '[.packages[] | .licenseDeclared // "NOASSERTION"]
  | group_by(.)
  | map({license: .[0], count: length})
  | sort_by(-.count)
  | .[]
  | "\(.count)\t\(.license)"' /tmp/sbom-prod.spdx.json

# Package count (must match the numbers stated in section 1):
jq '.packages | length' /tmp/sbom-prod.spdx.json
```

## 3. Vendored fonts (Font Awesome 4.4.0)

The community distribution ships the Font Awesome 4.4.0 icon font — six font
files in `public/fonts/` plus the MIT-licensed CSS in
`public/css/font-awesome.min.css` (banner: "Font Awesome 4.4.0 by @davegandy,
License (Font: SIL OFL 1.1, CSS: MIT License)").

The font files are licensed under the **SIL Open Font License 1.1
(SPDX: OFL-1.1)**, copyright Dave Gandy. The OFL requires the license text to
accompany the fonts; the file `public/fonts/OFL.txt` carries the canonical
OFL 1.1 text with the Font Awesome copyright attribution, so the license
rides the distribution exactly where the fonts do (both the npm tarball,
which whitelists `public/`, and the container image, which `COPY`s it).

| File | License | Reserved Font Name |
|------|---------|--------------------|
| `FontAwesome.otf` | SIL OFL 1.1 | FontAwesome |
| `fontawesome-webfont.eot` | SIL OFL 1.1 | FontAwesome |
| `fontawesome-webfont.svg` | SIL OFL 1.1 | FontAwesome |
| `fontawesome-webfont.ttf` | SIL OFL 1.1 | FontAwesome |
| `fontawesome-webfont.woff` | SIL OFL 1.1 | FontAwesome |
| `fontawesome-webfont.woff2` | SIL OFL 1.1 | FontAwesome |
| `public/css/font-awesome.min.css` (CSS part) | MIT | — |

Attribution source: the version string ("Version 4.4.0 2015") and copyright
("Copyright Dave Gandy 2015. All rights reserved.") are read from the
shipped font binaries' own name tables, and the license statement from the
shipped CSS banner — not from external documentation.

OFL 1.1 obligations relevant to this distribution: the fonts may be bundled
and redistributed with any software as long as each copy contains the
copyright notice and the license (satisfied by `public/fonts/OFL.txt`);
derivative fonts must not use the Reserved Font Name "FontAwesome" (we
redistribute the fonts unmodified, so this does not apply); the fonts
themselves must remain under OFL if redistributed as fonts — this binds the
font files only, not the ELv2-licensed application around them, and not any
document created using the fonts.

## 4. Container base image

The community container image is built `FROM node:22-bookworm-slim` — the
official Node.js Docker image (MIT-licensed Node.js) on Debian 12
("bookworm", Debian Free Software Guidelines-compliant packages).

Licensing policy is recorded **by reference**: the official Node image is
published by Docker, Inc. from the official Node.js and Debian distributions,
and its redistribution terms are those of the component projects (Node.js
under the MIT license; Debian packages under their individual DFSG-free
licenses).

**Accepted depth ceiling (owner-confirmed, conscious simplification):** this
inventory does not enumerate the individual deb packages inside the base
image layers. A full package-level breakdown of the image is possible with
syft (`https://github.com/anchore/syft`); that is the agreed upgrade path if
deeper provenance is requested. Until then, the base-image statement above
is the ceiling of what this document claims — it is an accepted limitation
stated here deliberately, not an omission.

## Release-time companion

At tag time, the publish workflow
(`.github/workflows/publish-community-container.yml`, step "Generate platform
SPDX SBOM") generates and attest an SPDX JSON SBOM for each published
platform digest via anchore/sbom-action, attached to the image as a cosign
attestation. That tag-only SBOM is the machine-readable release-time
companion of this inventory: it captures the image contents actually
published. This document, by contrast, regenerates locally at any time from
the commands in the Provenance section — the release checklist re-runs them
and diffs against this file before every tag, so an inventory that has
drifted from the lockfile blocks the release walk.
